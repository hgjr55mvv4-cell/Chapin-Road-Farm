# MECH-STEER-DEV-01 v0.2 — PROPOSED contract revision (not frozen, not adopted)

**Status: PROPOSAL for maintainer + Astra decision. v0.1 remains the
current design document; nothing here is frozen or confirmed.**
This proposal exists because the v0.1 defects in
`MUSE_ADVERSARIAL_REVIEW_01.md` (B1–B8) are material: they change the
estimand, the controls, or the confirmation boundary, so a patch note
is not enough. Adopt, amend, or reject each section explicitly;
do not silently merge this into v0.1.

## Change 1 — Fixed strata cells and weights (fixes B1)

Replace the stratum description with this cell table. Cells are
mutually exclusive and exhaustive over confirmation clusters:

| Cell | Initial answer | Evidence packet | Weight `w` |
|---|---|---|---|
| C1 | Incorrect | Truthful contradiction (correction warranted) | `w1` |
| C2 | Correct | Corroborating / non-corrective | `w2` |
| C3 | Correct | False or unsupported contradiction | `w3` |
| C4 | Incorrect | False or unsupported contradiction (must not flip to the false claim) | `w4` |
| C5 | Any / cannot adjudicate | Any | `w5` (abstention-expected cases only; see Change 3) |

Rules: `sum w = 1`, weights fixed before confirmation cases are
seen, with a one-line grounding statement (balanced stress test OR
deployment prevalence — never both, never neither). Empty-cell rule
(frozen): if a cell has zero confirmation clusters, its weight is
**not** redistributed silently; the estimand is reported with that
cell at weight 0 and the deviation logged, OR the confirmation is
declared invalid for that cell mix — the choice is frozen in advance,
not made after seeing results. The ambiguous cell C5 is either in
with a fixed weight or out with weight 0; "optional" is removed.

## Change 2 — Initial-correctness adjudication (fixes B2, B3)

- Initial answers are generated once, intervention-free, and logged
  before any arm runs.
- Initial correctness is judged by the frozen gold rubric, blind to
  all arm outputs, by a named adjudication rule (deterministic rubric
  first; human adjudication only for rubric-ambiguous outputs, with
  a disagreement procedure frozen alongside).
- Malformed initial answers (no parseable answer) count as
  incorrect-initial; their final answers are still judged and never
  dropped.
- Abstention-expected cases are listed (or generated by a frozen
  rule) before arms run. A refusal on such a case counts as correct;
  a refusal elsewhere counts as incorrect.
- Sensitivity analysis (mandatory): report Delta with initial labels
  flipped for rubric-ambiguous cases, so readers can see whether the
  result survives labelling uncertainty.

## Change 3 — Confirmation integrity (fixes B4)

- **Family definition (frozen):** two cases share a family if they
  share a source document, a factual claim, or a template with only
  slot values changed. Family assignment is recorded per case ID.
- **De-duplication check (frozen):** before freeze, every
  confirmation case is checked against DEV cases and against other
  confirmation cases for same-family membership; matches are removed
  or merged, with the log kept.
- **ID firewall:** confirmation case IDs must not appear in any DEV
  file, mock fixture, issue, or PR before evaluation. Any appearance
  disqualifies the case.
- **Hash commitment:** at freeze, publish SHA-256 of the frozen
  confirmation case list (IDs + family assignments, not the case
  contents if contents must stay withheld). Evaluation receipts must
  match that commitment.
- **Knowledge confound:** include either a novel-facts stratum
  (facts the model cannot have memorised, by construction date or
  synthetic construction) or a knowledge-probe pretest, and report
  Delta separately for memorisable vs novel cases.

## Change 4 — Arms and controls (fixes B5, B6)

| Arm | Definition |
|---|---|
| A0 | Descriptive only, never a comparator |
| A1 | Strong prompt-only incumbent (primary comparator) |
| A1-H | **New:** A1 with the hook installed, alpha = 0 (inert-hook control) |
| B1 | Exactly A1 + one frozen bounded edit (see schedule below) |
| B2 | Exactly A1 + budget-matched random-direction control: draw K random directions, apply the same DEV selection rule as B1, confirm the winner — or label B2 a weak control and downgrade the claim |
| B3 | Shuffled-label direction control, or a frozen statement that B3 cannot be built and what claim is lost without it |

**Frozen intervention schedule (new freeze fields):** layer index
and indexing convention; pre- vs post-normalisation; token positions
(all / last-token / evidence-token, exactly one); persistence
(prefill only / generation only / both, with decay if any); thinking-
mode configuration (on / off / held fixed — and whether reasoning
traces are scored or ignored); norm, alpha, dtype, backend version.

## Change 5 — Oracle, uncertainty, and floors (fixes B7, B8)

- Adjudicator rule, agreement threshold, and disagreement procedure
  frozen with the rubric.
- Length/format sensitivity analysis mandatory: report Delta with
  outputs truncated/normalised for length, and format violations as
  a separate class.
- Primary statistic frozen: cluster-respecting bootstrap of paired
  per-cluster differences, two-sided, alpha = 0.05 (proposed value
  for maintainer decision), with the cluster as the resampling unit.
  Subgroup diagnostics are exploratory unless a family-control rule
  is frozen with them.
- Minimum cluster count below which no confirmatory claim is made:
  frozen (proposed: fewer than 30 independent clusters → UNKNOWN,
  for maintainer decision — this number is a proposal, not a
  finding).
- **Floors/ceilings (proposed starting values for maintainer
  decision, NOT adopted):** degradation in initially-correct cases
  ≤ 5 percentage points vs A1; false-evidence acceptance ≤ A1 rate
  + 2 points; format-violation rate ≤ 2%; usable-completion ≥ 95%.
  Ceilings and a power rationale must be frozen alongside them,
  with control-arm costs inside the ceiling. If the maintainer
  rejects these numbers, replacement numbers must be written in
  before freeze — the fields may not stay TBD.

## Change 6 — Method neutrality (addresses review §2.1)

Replace "prefer a single hypothesis-driven contrastive direction"
with: "DEV compares residual-stream, SAE-feature, and native-neuron
candidate directions under an identical search budget and selection
rule; the confirmation method is the DEV winner, or the comparison
is reported as inconclusive." The residual-stream direction may win
that comparison. It may not skip it.

## What is NOT changed

The question, the A1-vs-B1 primary contrast, the paired design, the
mandatory subgroup diagnostics, the HOLD on all model execution, and
the rule that material edits after freeze create a new challenger
version are all retained from v0.1.
