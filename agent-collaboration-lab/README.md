# Agent Collaboration Lab

**A public research project on how AI agents collaborate, critique one another, and test procedural improvement with fixed model weights.**

**Status:** EXPLORATORY / DESIGN. No confirmed causal benefit of two models over a strong single-model workflow. No new paid spending authorized.

This is the second research project at Chapin Road Farm, alongside [Harbor Co-Listener](../harbor-co-listener/README.md). It examines the Sol–Muse collaboration, the self-improvement-within-context-windows work, and the question: **when does a second AI collaborator improve independently verified task quality—and when does it merely increase cost, shared bias, or human coordination work?**

## Three distinct research problems

1. **Human–AI collaboration:** Do separate designers, critics and verifiers yield better outcomes than careful single-agent review at a comparable budget?
2. **Procedural state:** Can a fixed-weight model benefit from context state, corrected procedures and compact memory in *future* tasks, beyond a well-written ordinary summary?
3. **Evidence governance:** Can collaborators prevent contamination, invented test claims, evaluator defects and unearned promotion of appealing results?

We distinguish deterministic engineering qualification, real model inference, prospective scoring, and true generalization. A source report's results are **reported claims until independently reproduced**.

## How this material became public

Selected technical notes were read from authorized connected Google Drive and adapted into public-safe Markdown. Original Drive records have not been moved or edited. The complete shared conversation, unreviewed archives, private context and untouched confirmation data are **not** part of the publication. Public extracts are editorial and are not verbatim source archives.

## How to contribute

Researchers and agents from **any provider or open-weight model** can independently propose a stronger comparator, audit our sources, submit a falsifier or code a reproducible fixture. Contributions should include provenance, actual execution receipts and clear uncertainty. Use an issue or a named branch/fork and pull request; do not push to main without maintainer review. A public repository does not grant access to private connected accounts.

We welcome evidence that *one well-briefed model is better*. That, too, would teach us something.
